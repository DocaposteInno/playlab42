L'Entraînement

Vous connaissez maintenant la propagation avant et la rétropropagation. Mais comment orchestrer tout ça pour qu'un réseau apprenne vraiment ? C'est le rôle de la boucle d'entraînement.

La Boucle d'Entraînement

Entraîner un réseau, c'est répéter le même cycle de 4 étapes :

1️⃣

Forward

Calculer la prédiction

2️⃣

Loss

Mesurer l'erreur

3️⃣

Backward

Calculer les gradients

4️⃣

Update

Corriger les poids

training_loop.py 
pour epoch de 1 à nb_epochs:
    pour batch dans données_entraînement:
        # 1. Forward : calculer la prédiction
        prédiction = réseau.forward(batch.entrées)

        # 2. Loss : mesurer l'erreur
        erreur = fonction_perte(prédiction, batch.cibles)

        # 3. Backward : calculer les gradients
        gradients = réseau.backward(erreur)

        # 4. Update : corriger les poids
        optimiseur.mettre_à_jour(réseau.poids, gradients)

Epochs, Itérations et Batchs

Les définitions clés

📦

Batch (lot)

Sous-ensemble de données traité en une fois. Tailles typiques : 32, 64, 128.

🔁

Itération (step)

Une mise à jour des poids = traitement d'un batch.

🔄

Epoch

Une passe complète sur TOUTES les données d'entraînement.

Exemple concret

Vous avez 1000 images et des batchs de 32 images :

  • • 1 epoch = 1000 ÷ 32 ≈ 31 itérations
  • • 10 epochs = 31 × 10 = 310 itérations (mises à jour des poids)
  • • Le réseau voit chaque image 10 fois au total

Pourquoi des batchs ?

Tout d'un coup

Gradient précis mais très lent

❌ Ne rentre pas en mémoire

Un par un (SGD)

Très rapide mais chaotique

⚠️ Gradient bruité

Mini-batch ✓

Équilibre vitesse/précision

✓ Optimisé pour GPU

Séparer ses données : Train / Validation / Test

On ne peut pas évaluer un modèle sur les données qu'il a utilisées pour apprendre — ce serait comme un étudiant qui passe l'examen avec les réponses sous les yeux.

📚

Training (70-80%)

Les données sur lesquelles le modèle apprend. C'est le manuel de cours.

📝

Validation (10-15%)

Pour ajuster les hyperparamètres et détecter l'overfitting. C'est l'examen blanc.

🎓

Test (10-15%)

Évaluation finale, utilisé UNE SEULE FOIS. C'est l'examen final.

Le piège de l'Overfitting

🎓

L'analogie de l'étudiant

Underfitting : L'étudiant ne lit que les titres des chapitres. Il ne comprend pas assez pour répondre aux questions.
Overfitting : L'étudiant mémorise chaque mot du manuel. Il récite parfaitement les exercices, mais face à une question légèrement différente, il est perdu.
Bon ajustement : L'étudiant comprend les concepts et sait les appliquer à de nouvelles situations.

Underfitting

Le modèle est trop simple. Il n'apprend pas assez.

Symptôme : Loss élevée sur train ET validation

Overfitting

Le modèle mémorise au lieu de comprendre.

Symptôme : Loss basse sur train, élevée sur validation

Combattre l'Overfitting : La Régularisation

La régularisation regroupe toutes les techniques qui empêchent le modèle de "tricher" en mémorisant.

⏹️

Early Stopping

Arrêter l'entraînement quand la validation loss cesse de s'améliorer.

Le plus simple et le plus efficace

🎲

Dropout

"Éteindre" aléatoirement certains neurones pendant l'entraînement.

Force le réseau à ne pas trop dépendre d'un neurone

📏

L1 / L2

Pénaliser les poids trop grands pour garder le modèle simple.

L1 = sélection de features, L2 = lissage

🔄

Data Augmentation

Créer des variations des données (rotation, zoom, flip...).

Plus de données = moins d'overfitting

🎯

Ce qu'il faut retenir

  • • Boucle : Forward → Loss → Backward → Update (répéter)
  • • Epoch = 1 passage complet sur les données
  • • Train/Val/Test : 3 ensembles séparés pour apprendre, ajuster, évaluer
  • • Overfitting : le modèle mémorise au lieu de comprendre
  • • Early stopping : s'arrêter quand la validation stagne
