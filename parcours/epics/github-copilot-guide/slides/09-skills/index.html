Skills : apprendre une procédure à l'agent

Un Agent Skill est un dossier contenant un fichier SKILL.md et, éventuellement, des ressources ou scripts. Il décrit une méthode de travail que Copilot peut charger lorsqu'une tâche correspond à sa description.

Exemples : préparer une revue, appliquer les conventions d'un framework, analyser un document ou réaliser une procédure de migration. Un skill n'entraîne pas le modèle et ne crée pas automatiquement un sous-agent.

Pourquoi ne pas tout mettre dans les instructions ?

MécanismeQuestion à laquelle il répondExemple
InstructionsQuelles règles respecter dans ce dépôt ?Commandes de test, stack, conventions de nommage.

Dans la documentation de septembre 2026, les .prompt.md sont dépréciés pour Agent Host. Les skills sont le choix conseillé pour de nouvelles procédures portables.

Un exemple versionné avec le dépôt

.github/
  skills/
    preparer-revue/
      SKILL.md
      references/
        checklist.md

Le fichier SKILL.md commence par un frontmatter YAML :

---
name: preparer-revue
description: Préparer une revue de code à partir d'un diff, en recensant les changements, risques et validations nécessaires. À utiliser quand une revue de modifications est demandée.
---

# Préparer une revue

1. Lire les instructions du dépôt et le diff fourni.
2. Identifier les fichiers et contrats concernés.
3. Appliquer la checklist de [revue](references/checklist.md).
4. Distinguer les bugs démontrables des hypothèses à confirmer.
5. Produire un compte rendu : fichier, risque, justification,
   commande de validation proposée et limites de l'analyse.

Ne pas modifier les fichiers ni publier de commentaire sans accord.
Ne jamais recopier de secret découvert dans le résultat.

Utilisez un nom court et explicite, cohérent avec le dossier. La description explique à la fois la capacité et les situations où l'employer. « Aide au développement » est trop large ; « préparer une revue de diff » est testable.

Chargement progressif

  1. Copilot découvre les métadonnées des skills disponibles.
  2. Lorsqu'un skill est pertinent, il lit son SKILL.md.
  3. Il consulte les ressources liées ou exécute les scripts nécessaires, selon les permissions du client.

Gardez le corps lisible et déplacez les longs exemples dans des fichiers de référence. Reliez-les explicitement depuis SKILL.md plutôt que de supposer qu'un agent explorera tout le dossier.

Découvrir et utiliser

Dans Copilot CLI, /skills permet de gérer les skills ; /env aide à inspecter les capacités chargées. Dans VS Code, /skills ouvre leur configuration. Vous pouvez invoquer explicitement un skill par son nom slash dans les clients compatibles :

/preparer-revue
Prépare une revue du diff actuel avec la procédure preparer-revue.
Reste en lecture seule et cite les fichiers concernés.
Si ce skill n'est pas disponible, signale-le.

Les clients qui prennent en charge les skills peuvent en activer un automatiquement selon la description. Vérifiez le chargement réel dans les traces ou les détails proposés par le client ; mentionner un nom dans un prompt n'est pas une preuve.

Qualité et sécurité

  • Une responsabilité claire par skill ; ne recopiez pas toutes les instructions générales.
  • Des critères de réussite, des erreurs à signaler et un format de sortie précis.
  • Des scripts limités au besoin, inspectés avant exécution et sans secret embarqué.
  • Une provenance fiable : un skill téléchargé est du contenu actif, pas une simple documentation inoffensive.
  • Des essais sur des demandes pertinentes et non pertinentes pour vérifier le déclenchement.
Limite importante : « lecture seule » écrit dans un skill reste une consigne. Restreignez également les outils et permissions si cette propriété est nécessaire.

Où les clients cherchent-ils les skills ?

PortéeEmplacements documentés

Personnel — CLI~/.copilot/skills/, ~/.agents/skills/
Personnel — VS CodeLes deux précédents et ~/.claude/skills/

Privilégiez une source partagée dans le dépôt, pas trois copies du même skill. Gardez les préférences personnelles hors du dépôt. Un chemin reconnu par un client n'est pas une garantie de découverte identique dans tous les clients.
