VS Code : agents, sessions et configuration

Copilot ne se limite plus à un panneau de questions. VS Code propose un environnement pour préparer, exécuter et suivre des tâches agentiques. Le bon point de départ reste une session courte, un périmètre clair et des autorisations limitées.

Référence stable : VS Code 1.140, publiée le 30 septembre 2026. La version 1.141 est encore Insiders à la date du guide. Ses fonctionnalités ne doivent pas être présentées comme disponibles dans toutes les installations stables.

La nouveauté structurante : le harness Copilot

Un harness est le runtime qui exécute l'agent et relie modèles, outils et permissions. La stable 1.140 met en avant le harness Copilot, fondé sur le Copilot SDK comme le CLI, et exécuté par un processus Agent Host. Il peut devenir le choix par défaut pour certains utilisateurs, pas nécessairement tous.

Distinguez cinq choix : cible/harness → agent → modèle → permissions → isolation du code. « Cloud » est un environnement d'exécution ; « Plan » un agent ; un worktree une isolation des modifications Git, pas du réseau ni des commandes.

Sessions locales, en arrière-plan et dans le cloud

La gestion des sessions permet de lancer et retrouver plusieurs tâches. Choisissez l'environnement disponible dans votre version plutôt que de confondre toutes les sessions avec le Chat actif.

EnvironnementIntérêtPoint de vigilance
Harness LocalRuntime de l'extension host VS Code, avec outils intégrés et d'extensions.Travaille dans le workspace courant ; « Local » désigne ici un harness.
Harness Copilot / Agent HostSessions interactives ou en arrière-plan, sur votre machine, un hôte distant ou un Dev Container.Choisir Folder ou Worktree et vérifier les permissions ; l'arrière-plan n'est pas nécessairement le cloud.
CloudTravail distant avec une proposition de changements sur GitHub.Accès au dépôt, politiques, coûts et revue de la PR.

Le mode d'exécution peut changer les outils disponibles. Vérifiez le contexte transmis lors d'une reprise ou délégation ; ne supposez pas qu'une session distante voit vos fichiers locaux non publiés.

Attention aux sessions Worktree Copilot : la documentation actuelle indique qu'elles utilisent Allow all. Les sessions Folder permettent les permissions manuelles. Choisissez en connaissance de cause ; un worktree n'est pas un sandbox.

Les sessions Agent Host peuvent contenir des peer chats, avec historiques et modèles séparés mais normalement le même workspace/worktree. Plusieurs chats peuvent donc entrer en conflit sur les fichiers. Les sessions multi-dossiers introduites en 1.140 sont Experimental, désactivées par défaut.

Quel lien avec Copilot CLI ?

Le CLI fonctionne seul dans un terminal, y compris le terminal intégré de VS Code. Il peut se connecter au workspace via /ide. VS Code peut également proposer des sessions CLI dans son environnement de sessions.

Utilisez le profil terminal GitHub Copilot CLI, Chat: New Copilot CLI Session ou copilot dans le terminal. Resume in Terminal permet de poursuivre une session Copilot dans le CLI. Le runtime commun favorise la réutilisation d'instructions, skills et hooks compatibles, pas la synchronisation de tous les réglages.

Deux interfaces ne signifient pas deux projets différents : vous pouvez partager les fichiers de personnalisation du dépôt. En revanche, le Chat VS Code et le CLI gardent leurs commandes, leurs paramètres et leurs autorisations propres.

Certaines fonctions peuvent être expérimentales ou activées progressivement. Consultez les notes de version, notamment lorsque l'interface ou un réglage manque. N'activez pas tout uniquement parce qu'une fonctionnalité existe.

À distinguer du socle stable : HydraFusion est une Research Preview ; la délégation à des agent hosts distants est Experimental ; les agents cloud tiers Claude/Codex sont Preview. Le suivi Background Shells et la comparaison Run and Compare Agents… figurent dans les notes Insiders 1.141.

Configuration minimale, plutôt qu'un bloc obsolète

{
  "github.copilot.enable": {
    "*": true,
    "plaintext": false
  },
  "github.copilot.nextEditSuggestions.enabled": true
}

Ouvrez ensuite les paramètres de VS Code, recherchez les options Chat/Copilot et utilisez les réglages documentés par votre version. Ne recopiez pas aveuglément d'anciens flags de preview, des noms d'outils ou un compteur de requêtes comme s'il s'agissait d'un plafond de facture.

Stockez les réglages partageables au niveau du workspace, les préférences au niveau utilisateur et les secrets dans les mécanismes d'authentification appropriés. Les politiques d'entreprise peuvent primer sur un réglage local.

JetBrains et Visual Studio

JetBrains expose les réglages du plugin dans Settings → Languages & Frameworks → GitHub Copilot. Visual Studio dispose de ses paramètres GitHub Copilot et d'un contexte de solution adapté à .NET.

Le support des instructions ciblées, prompts, skills, agents ou MCP évolue indépendamment selon chaque IDE. Vérifiez les capacités de votre version ; une ancienne matrice « oui/non » peut être trompeuse.
