GitHub Copilot : de l'assistant aux agents

GitHub Copilot est une suite d'outils d'assistance au développement. On peut lui demander une suggestion de code, une explication, un plan ou l'exécution d'une tâche avec des outils. Le choix dépend du besoin et du niveau de contrôle souhaité.

État du guide : 3 octobre 2026. Les fonctionnalités peuvent dépendre de la version, du plan, du déploiement progressif et des politiques d'organisation. Ce guide distingue les principes durables des informations tarifaires et des commandes susceptibles d'évoluer.

Les anciennes Copilot Extensions ne sont pas un synonyme de MCP. De même, les APIs d'administration ou de consommation Copilot ne sont pas une API généraliste d'inférence comprise dans n'importe quel abonnement.

Pour intégrer un runtime agentique dans une application, le Copilot SDK officiel communique avec le serveur CLI via JSON-RPC. C'est une architecture différente d'une simple API REST de complétion ; son installation et ses conditions d'usage se vérifient séparément.

Comprendre les offres avant de choisir

GitHub propose des offres de découverte, des abonnements individuels et des licences d'organisation. La disponibilité d'un modèle ou d'un agent ne se déduit pas seulement du prix de l'abonnement.

Type d'offreÀ examiner
Découverte / FreeLimites, fonctionnalités accessibles et conditions d'éligibilité.
Pro / Pro+ / MaxPrix, AI credits de base, allocation flex variable et consommation supplémentaire.
Business / EnterpriseSeats, politiques, accès aux modèles et outils, données et contrôle des dépenses.

Le chapitre Facturation explique le passage aux AI credits, les quotas et les budgets. Consultez toujours votre compte GitHub pour connaître les droits et conditions réellement applicables.

Connexion, données et responsabilités

L'accès s'appuie sur un compte GitHub et ses droits. En organisation, un administrateur peut attribuer les licences et définir les politiques. Vérifiez l'entité qui paie et le dépôt autorisé avant d'utiliser un agent distant.

Un traitement par un service distant n'est pas une exécution entièrement locale. Vérifiez les engagements de votre offre et les paramètres de données ; n'extrapolez pas les garanties Business/Enterprise à un compte individuel ou à un outil tiers.

Copilot reste un assistant : vous êtes responsable du code accepté, des permissions accordées et de la livraison. « L'agent l'a fait » ne remplace ni compréhension, ni test, ni revue.

Choisir un modèle sans apprendre une liste par cœur

Les catalogues et modèles par défaut changent. Utilisez le sélecteur de modèles dans VS Code ou /model dans le CLI. Vérifiez la disponibilité, le coût et l'adéquation à la tâche plutôt que de choisir systématiquement le modèle le plus coûteux.

Une tâche courte de documentation n'a pas les mêmes besoins qu'un raisonnement architectural. Fournir un contexte pertinent et des critères précis peut compter davantage qu'un changement de modèle.

Les IDE ne sont pas équivalents

GitHub Copilot est proposé dans VS Code, Visual Studio, des IDE JetBrains, Xcode et Neovim, avec des périmètres différents. Ce guide détaille surtout VS Code et Copilot CLI ; pour les autres IDE, vérifiez la documentation de leur extension plutôt qu'une matrice figée.

Ce que vous saurez faire

  • Débuter avec une suggestion et une modification de faible risque.
  • Configurer instructions, agents et skills sans les confondre.
  • Choisir entre Ask, Plan, Agent, CLI, Fleet et délégation cloud.
  • Relier un outil MCP avec des droits adaptés au besoin.
  • Maîtriser contexte, permissions, consommation et revue du résultat.
