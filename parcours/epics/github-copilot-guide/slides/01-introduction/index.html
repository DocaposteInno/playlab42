Démarrer et choisir son parcours

Mise à jour : 3 octobre 2026. Ce guide couvre les bases, les agents dans VS Code et Copilot CLI. Les modèles, quotas et fonctionnalités évoluent vite : les sources de chaque chapitre et l'aide de votre version priment sur un exemple figé.

Le menu du parcours permet de rejoindre directement un chapitre. Il n'est pas nécessaire d'activer MCP, Fleet ou Autopilot pour profiter de Copilot.

1. Activer Copilot dans VS Code

  1. Mettez VS Code à jour, ouvrez un petit dépôt de confiance puis ouvrez Chat et la configuration Copilot.
  2. Connectez votre compte GitHub. Vérifiez l'offre active et, en entreprise, les politiques appliquées par votre administrateur.
  3. Suivez l'assistant d'installation de votre version ; vérifiez ensuite que les suggestions et le Chat sont disponibles.

Dans JetBrains, installez le plugin GitHub Copilot depuis les paramètres. Dans Visual Studio, utilisez l'intégration Copilot proposée par votre version. Les commandes et réglages ne sont pas interchangeables entre IDE.

2. Comprendre avant de modifier

Ouvrez un fichier, sélectionnez une petite fonction et choisissez Ask dans Chat si votre harness le propose (notamment Local). Sinon, demandez explicitement une explication dans une session aux permissions limitées :

Explique cette fonction à un développeur qui découvre le projet.
Décris les entrées, la sortie et les cas limites.
N'effectue aucune modification.
Si une hypothèse manque, indique-la au lieu de l'inventer.

Le Chat inline s'ouvre avec Ctrl+I sous Windows/Linux ou Cmd+I sous macOS. Vérifiez les raccourcis de votre installation si votre keymap diffère.

3. Réaliser une première modification limitée

Sur une branche dédiée, choisissez Agent dans une session Local ou Copilot Folder avec permissions manuelles. Évitez de démarrer par une session Worktree Copilot, qui utilise actuellement Allow all. Donnez un résultat mesurable :

Ajoute un test pour le cas vide de cette fonction.
Réutilise le framework et les conventions existants.
Ne modifie pas l'API publique et n'ajoute pas de dépendance.
Annonce les fichiers visés, puis demande les permissions nécessaires.
Lance les tests ciblés et explique le diff obtenu.

Relisez le diff et les résultats avant d'accepter. Une exécution réussie n'implique pas que le besoin métier est correctement couvert.

4. Donner les repères du dépôt

Créez un court .github/copilot-instructions.md, adapté au projet réel :

# Instructions du projet
- Lis les conventions existantes avant de modifier un fichier.
- Réutilise les commandes de test et de build documentées.
- Préserve les API publiques sauf demande explicite.
- Demande l'accord avant toute dépendance ou publication.
- Ne place jamais de secret dans le code ou les journaux.

Dans le CLI, /init peut proposer ces instructions. Relisez-les, versionnez seulement ce qui est juste, puis contrôlez leur chargement avec /instructions.

Le vocabulaire à connaître

TermeCe qu'il désigne
Complétion / NESSuggestion pendant la frappe / suggestion de la prochaine modification.
Ask / Plan / AgentComprendre / préparer / exécuter. Ce sont des modes ou agents, pas des garanties de permissions.
InstructionsConventions durables du dépôt ou de l'utilisateur.
Prompt réutilisableUne demande Local existante ; les .prompt.md ne sont plus chargés par Agent Host.
Agent personnaliséUn rôle spécialisé, avec des instructions et des outils.
SkillUne procédure réutilisable, avec éventuellement scripts et ressources.
MCPUn protocole donnant accès à des outils ou données externes.
FleetLa coordination de sous-agents en parallèle dans Copilot CLI.
AI creditsL'unité de consommation de la nouvelle facturation Copilot ; pas un nombre de prompts.
Les commandes ont un contexte. Tapez / dans VS Code pour ses actions et prompts disponibles. Tapez /help dans le CLI pour son propre catalogue. Ne copiez pas une commande de l'un en supposant qu'elle fonctionne dans l'autre.
